# Regional scene authoring protocol

Use protocol:2 and action:future for a landscape or district, rather than one giant asset. Read read_protocol for the exact JSON Schema. A package has protocol,id,version,title,description,assets,region. Use the supplied newRelease identity. Do not include legacy terrain in a regional package.

inspect_scene supplies regionalSite: center, radius, transition and elevation. Use this fresh site to preserve explored chunks. Coordinates in region.center are absolute world x/z; operator offsets, placement positions and road points are local x/z relative to that center. All layout should fit in the inner disk radius-transition. The engine freezes all explored chunk versions at application and fades regional modifications before protected boundaries. Regions are spatially bounded. Later regions replace/blend surfaces inside their own footprint; they do not add another global sine-noise layer.

region requires center,radius(60..240),transition(12..100; <=radius/2),elevation,operators,surface,clearing,requirements. preserveCorridors defaults true and protects existing roads, river channels and their supporting surfaces. Keep it true when the user requests preserved passages. For a completely planned city platform set preserveCorridors:false and clearing.settlements:true; old explored chunks remain protected regardless. Optional roads,placements,scatter,vehicles,unsupported default empty. surface={color:'#RRGGBB',snowCover:boolean,rockColor?:'#RRGGBB'}; clearing={vegetation:boolean,rocks:boolean,settlements:boolean}.

The region surface starts at the absolute elevation, then applies operators. ridge={kind:'ridge',height,wavelength,angle,offset:{x,z}} produces continuous mountain ridges across chunks. volcano={kind:'volcano',height,radius,craterRadius,craterDepth,offset:{x,z}} produces a cone, raised rim and depressed crater (craterRadius<0.8*radius, craterDepth<=height); choose craterRadius>=15m for resolvable low-poly geometry. terrace={kind:'terrace',height,radius,offset:{x,z}} creates a smooth raised or depressed platform. An empty operators list creates an actual flat district platform, replacing original hills. Snow-covered landscapes need a pale surface and substantial ridge relief; decorative snowdrifts alone do not satisfy a snowfield. Dark rocks alone do not satisfy a volcano.

Roads: {id,points:[{x,z},...],width:4..16,closed:boolean}. The engine projects real paved road meshes onto the terrain. Closed roads connect the last point back to the first. Roads used by vehicles must lie entirely on flat, fully affected terrain, with no part in the transition or protected zone. For city requests create connected roads and several independently editable building placements, not a city diorama. A compact perimeter loop plus connected inner streets works; leave enough lot clearance.

Placements: {id,asset,position:{x,z},rotation:0,scale:1,role:'building'|'prop',foundation:true}. Buildings and their full footprints must lie on flat ground, clear of road strips and other buildings. Clearance uses conservative footprint bounds: keep building centers at least half the road width plus the building half-diagonal away from all road segments. Each building gets its own stable ID and collision. Clearing vegetation/rocks/settlements reserves the district rather than trying to scatter towers into a forest. The world clock, old chunks and camera are unchanged.

Assets retain literal box/sphere/cone/cylinder parts (maximum 32), position components -32..32 and size components <=32. Optional part.emissive='#RRGGBB' enables emissive volcanic detail. For a tall building use collider:null and colliders:[{halfExtents:[...],center:[...]}] for compound collisions, up to 16 boxes (half extents<=32, center components<=64). Keep boxes inside the visible geometry and cover the building body. Car assets should face local -Z, have a collider matching their body, and put the bottom at y=0. Vehicles must be separate assets and runtime actors, not boxes permanently attached to buildings.

Vehicles: {id,asset,road:'closed-road-id',speed:0.5..15,phase:0..1}. Use at least two vehicles for a plural request, with phases well separated. These really move using the absolute world clock and kinematic Rapier bodies. Pausing freezes them; unloading and returning samples their current route position. This is fixed-speed closed-route traffic; autonomous navigation, signals, avoidance, wheel/suspension physics are unsupported. Include any specifically requested unsupported behavior in region.unsupported and explain it instead of claiming completion.

Scatter can have multiple rules: {asset,count,clearance}; it is decorative and never substitutes for required structures. Every asset intended to appear must be referenced by a placement/scatter/vehicle. Sample the full scene with compile_validate_stage, inspect its completion report, then repair failures before submit_edit. Validation measures the generated mesh relief, actual snow coverage and crater depth, independent building count/height, traversable roads and moving vehicles. It rejects zero-generation scenes and unsafe lots/routes. Do not weaken criteria to pass.

requirements is an object with numeric minimums: minRelief,minSnowCoverage,minCraterDepth,minBuildings,minBuildingHeight,minTallBuildings,minRoadLength,minVehicles,minMovingVehicles (unspecified values default to zero). Set criteria appropriate to the user's full request. The host also enforces minimums for explicitly requested snowfields/mountains/volcanoes/cities/skyscrapers/driving vehicles. Snowfield mountains should have >=20m relief and >=0.65 snow coverage; volcanoes >=25m relief and >=8m measured crater depth; a city >=4 buildings and >=100m roads, at least 2 skyscrapers >=25m high, moving cars >=2 moving vehicles. Unsupported features must remain visible in the partial-completion report.

Compile validates generated geometry, not just the schema. A passed preflight is not proof the user has visited the region. submit_edit proposes deployment; host application rechecks against the latest explored chunks. Report the site and distinguish published/preflight-passed/loaded, with explicit unsupported parts.

Only list explicitly requested but unimplemented features in unsupported. General limitations (for example no avalanche simulation when the user only asked for snow mountains) belong in description, not unsupported. Do not invent additional requested features.

A volcano can be flattened by preserved base roads at the proposed site. If the request does not require preserving roads/rivers inside the NEW region, set preserveCorridors:false explicitly (this NEVER changes protected explored chunks). If preserving them is requested, move the cone clear of the corridors. Increasing cone height will not fix a zero protection mask. For city platforms also use preserveCorridors:false. Batch write_plugin and compile_validate_stage in one response when possible; tools run sequentially.

Use write_validate_plugin(source) for creation and each repair. This combines the existing write_plugin and compile_validate_stage without weakening any check, reducing tool-round cost. Do not waste an extra model round calling compile_validate_stage after a passed write_validate_plugin.

Water regions: read the water skill. Optional region.water={kind:'ocean'|'lake',shoreColor:'#RRGGBB',shoreHeight:0.3..4} declares use of the engine's native world-level water. Carve real seabed below inspect_scene.waterSystem.level; do not tile flat assets into a fake ocean. Optional habitat:'land'|'underwater' on placements/scatter constrains actual placement. Water has additional measured geometry criteria that cannot be disabled. Existing regions without water retain their previous generation exactly.
